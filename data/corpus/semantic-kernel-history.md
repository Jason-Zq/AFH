# Semantic Kernel 简史

## 起源

Semantic Kernel（SK）是微软于 2023 年开源的企业级 AI 编排 SDK，首发 C#，后扩展 Python 与 Java。其定位从一开始就很明确：不是研究玩具，而是让传统软件工程团队把 LLM 能力嵌入现有应用的**编排层**。

## 核心概念

### 插件（Plugin/Function）

SK 把能力统一抽象为函数：原生函数（普通代码）与语义函数（提示词模板）地位相同，都可被 LLM 调用。这一抽象后来与 OpenAI 函数调用规范相互靠拢，成为工具集成的标准形态，也演化出对 MCP 等开放协议的支持。

### 规划器（Planner）

早期 SK 的明星概念：给定目标，由模型自动生成调用插件的步骤序列并执行。规划器展示了"LLM 即编排器"的愿景，但在生产实践中暴露出可靠性问题——动态生成的计划难以测试与审计，业界逐渐转向显式定义的工作流图，这一教训直接影响了后继框架的设计。

### 记忆与连接器

SK 提供向量存储、各类模型服务的统一连接器，强调依赖注入、遥测等企业级特性，与 .NET 生态深度融合。

## 演进：并入 MAF

SK 后期已加入 Agent 抽象（Agent Framework 子模块、Agent 间编排等）。为避免与 AutoGen 双栈并存，微软将二者整合为统一的 **Microsoft Agent Framework（MAF）**：SK 贡献企业级工程底座（连接器、DI、遥测、稳定 API），AutoGen 贡献多智能体编排研究。对既有 SK 用户，微软提供迁移路径；新项目应直接以 MAF 为起点，把 SK 视为其前身而非并行选项。
