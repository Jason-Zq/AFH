# 工具调用（Function Calling）机制

## 定义

工具调用是让语言模型与外部世界交互的标准机制：开发者以 JSON Schema 描述可用函数（名称、说明、参数），模型在需要时输出结构化的调用请求，由运行时执行真实函数并把结果回传给模型。

## 一次工具调用的完整链路

1. 应用把工具定义随用户消息一起发给模型；
2. 模型判断需要工具，返回 `tool_calls`（函数名 + 参数 JSON），而不是自然语言回答；
3. **运行时**（Harness）解析调用请求，执行对应函数；
4. 函数结果以 `tool` 角色消息追加到对话历史；
5. 再次调用模型，模型基于工具结果生成最终回答——或发起下一轮工具调用。

第 3-5 步构成"函数调用循环"，由 Harness 而非模型完成。模型只负责"决定调用什么"，从不直接执行代码。

## 编写好工具的原则

- **单一职责**：一个工具做一件事，参数尽量少；
- **说明即提示词**：函数与参数的 description 写给模型看，要说清"何时用、参数什么意思、单位是什么"；
- **返回模型可读的文本**：结构化结果格式化为紧凑文本，避免大段原始 JSON；
- **失败要有信息**：工具报错时返回有意义的错误描述，模型往往能据此自我修正重试；
- **幂等与安全**：写操作应要求审批；危险工具用审批流程（Human-in-the-loop）拦截。

## 常见问题

- **模型不调工具**：检查工具说明是否清晰、系统提示词是否明确要求使用工具；
- **参数幻觉**：模型编造参数值。缓解：在描述中给出示例值、在函数内做参数校验并返回纠错信息；
- **循环失控**：模型反复调用同一工具。Harness 的最大迭代次数（如 MaximumIterationsPerRequest）就是为此设计的刹车；
- **厂商差异**：不同模型服务对工具 schema 的严格程度不同（如早期某些 OpenAI 兼容服务对 schema 字段敏感导致 400 错误），接入新厂商时应先做工具调用冒烟测试。

## 在 Microsoft Agent Framework 中

.NET 侧用 `AIFunctionFactory.Create(方法)` 把普通 C# 方法变成 `AIFunction`，挂到 Agent 的 `ChatOptions.Tools` 即可；函数调用循环由框架内置的 `FunctionInvokingChatClient` 中间件驱动，HarnessAgent 则默认包含这一层。
