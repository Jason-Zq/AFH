# Agent 记忆体系

## 为什么 Agent 需要记忆

大语言模型本身是无状态的：每次调用只看到当次输入的上下文。要让 Agent 记得"昨天做过什么"、"这个用户偏好什么格式"，必须在模型之外构建记忆体系，并在每次调用时把相关记忆注入上下文。

## 三类记忆

- **短期记忆**：当前会话的对话历史。实现最简单（直接放进上下文），但受窗口容量限制，需要压缩与摘要机制配合；
- **工作记忆**：任务执行过程中的临时状态——计划、待办、中间结论。生命周期限于单个任务，任务结束即归档或丢弃；
- **长期记忆**：跨会话持久化的知识。常见载体是文件系统（笔记、Markdown 文件）和向量数据库（语义检索历史经验）。写入策略（记什么、何时记）比存储选型更影响效果。

## 文件记忆：朴素但有效

相比向量库，文件记忆有独特优势：可读、可编辑、可用 Git 管理、模型可以直接读写。典型做法是 Harness 在每次运行结束时把关键结论、踩过的坑、用户偏好写入约定的记忆目录，下次运行时按需加载。代价是规模大了之后检索退化为文件名约定与全文搜索。

## 在 Microsoft Agent Framework 中的对应关系

MAF 的 Harness 内置文件记忆能力：Agent 可以把工作笔记写入文件系统，跨会话复用，这与待办管理、历史持久化同属 Harness 的默认运行时职责。长期语义记忆则可由开发者自行接入向量存储——Harness 负责"记住"，框架层负责"存哪、怎么取"。

## 实践要点

记忆系统的常见陷阱是"什么都记"：噪声记忆会稀释检索质量。建议只沉淀三类内容——用户的稳定偏好、可复用的经验结论、未完成事项的状态，并配合定期清理。
