# 上下文工程（Context Engineering）

## 一句话概括

上下文工程是围绕"如何把正确的信息装进有限的上下文窗口"这一问题的工程实践：模型能力大体固定后，Agent 表现的上限往往由你喂给它的上下文质量决定。

## 上下文窗口里装了什么

一次模型调用的输入通常由以下几类内容组装而成：

- **系统提示词**：角色、规则、输出格式、可用工具说明，最稳定的部分；
- **对话历史**：用户消息、模型回复、工具调用及其结果，随轮次线性增长；
- **工具结果**：检索片段、文件内容、命令输出，往往是最大的 token 消耗来源；
- **记忆注入**：长期记忆、用户偏好、历史任务笔记，按相关性动态选取；
- **运行时状态**：待办列表、当前计划、环境信息等结构化上下文。

## 核心矛盾与常用手段

上下文窗口有限，而工具结果和历史会不断膨胀。常见手段包括：

- **历史压缩**：逼近窗口上限时，用摘要替换早期对话，保留关键事实与决定；
- **工具结果裁剪**：只回传相关片段而非整个文件，大结果落盘、上下文里留指针；
- **检索式注入**：按需检索而非全量塞入，记忆与知识遵循"相关性优先"；
- **提示词分层**：稳定内容前置以命中缓存，易变内容后置。

## 在 Microsoft Agent Framework 中的对应关系

MAF 的 Harness 默认内置了历史持久化与上下文压缩：会话历史自动保存，逼近上限时自动摘要压缩，开发者无需手写这套逻辑。这也意味着上下文工程的大部分"体力活"由运行时承担，开发者聚焦的是提示词与工具设计——上下文工程的重心正从"手工拼接"转向"配置与裁剪运行时默认行为"。
