# Agent 成本优化

## 成本结构

Agent 的成本 ≈ 模型调用次数 × 每次 token 数 × 单价。与普通对话不同，Agent 的多轮循环让两个乘数都容易失控，优化应同时针对三处下手。

## 模型分层

不要全程使用旗舰模型。按步骤难度分工：

| 步骤 | 典型选择 |
|------|----------|
| 规划、最终综合、疑难推理 | 大模型 |
| 分类、路由、抽取、摘要、工具参数填充 | 小模型 |

小模型成本常低一个数量级，而 Agent 循环中大量步骤其实是机械性判断。路由本身可以用规则或最小模型完成。

## 上下文压缩

历史是 token 消耗大头：

- 工具返回的长文本立即摘要或落盘，上下文只留结论与引用；
- 定期压缩对话历史，保留事实与决定，丢弃过程性寒暄；
- 子任务用独立上下文的子代理执行，只把结论带回主上下文。

## 缓存

- 系统提示词、工具定义等固定前缀命中厂商的提示词缓存，可显著降低重复计费；
- 对确定性工具（检索、查询）按参数做结果缓存，避免同一信息反复取；
- 缓存键设计要考虑版本：提示词或语料变了，缓存必须失效。

## 早停

- 答案充分即终止循环，不追求"把预算用完"；
- 检索类任务设定置信度门槛，达标即跳过后续精化步骤；
- 检测到原地兜圈立即中断，兜圈的每一轮都是纯浪费。

## 预算护栏

把成本当作一等约束写进运行时：单任务 token 上限、单轮工具调用上限、日级账单告警。超限时优雅降级（换小模型、缩减范围、请求人工）而非硬失败。护栏还兼作失控循环的最后保险——成本熔断往往比逻辑检测更早触发。
