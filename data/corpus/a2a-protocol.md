# A2A（Agent2Agent）协议

## 定位

A2A（Agent2Agent）是 Google 于 2025 年提出并捐赠给 Linux 基金会的开放协议，解决的是 Agent 之间的互操作问题：不同团队、不同框架、不同供应商构建的 Agent，如何互相发现、委派任务并协作。如果说 MCP 解决"Agent 连工具"，A2A 解决"Agent 连 Agent"。

## 核心概念

- **Agent Card**：Agent 对外发布的"名片"（JSON 文档），描述自身能力、技能、端点地址与认证方式，供其他 Agent 发现与决策是否委派；
- **任务（Task）**：协作的基本单元。客户端 Agent 把任务发给远端 Agent，任务有生命周期状态（提交、进行中、需要输入、完成、失败等），支持长时间运行与流式进度更新；
- **消息与产物**：任务过程中的多轮沟通以消息承载，最终交付物称为产物（Artifact），可以是文本、文件等。

## 与 MCP 的分工

两者是互补而非竞争关系：

| 维度 | MCP | A2A |
|------|-----|-----|
| 连接对象 | 工具与数据源 | 其他 Agent |
| 抽象粒度 | 函数级调用 | 任务级委派 |
| 交互模式 | 请求-响应，由调用方驱动 | 任务生命周期，可对等协作 |
| 典型场景 | 查数据库、读文件 | 把子任务外包给专业 Agent |

一个典型组合是：编排 Agent 通过 A2A 把任务委派给远端专家 Agent，专家 Agent 内部再通过 MCP 调用自己的工具。

## 实践要点

A2A 的价值在于跨组织、跨框架边界：同一进程内的多 Agent 协作用框架自带编排（如 MAF 的移交/群聊模式）更简单；只有需要对接外部独立 Agent 时，A2A 的标准化收益才会显现。
