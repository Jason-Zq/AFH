# CodeAct：用代码代替链式工具调用

## 定义

CodeAct 是让 Agent 直接生成可执行代码（通常是 Python）来表达行动的模式：模型不再一步步输出 JSON 格式的工具调用，而是写一段代码，在沙箱中一次执行，代码内部可以调用多个工具、做循环、写条件分支。

## 与链式函数调用的对比

传统函数调用模式下，Agent 每一步只发起一次（或一组）工具调用，结果回传模型后再决定下一步——十步任务就是十次模型往返。CodeAct 把"多步决策"下放到代码层：

| 维度 | 链式函数调用 | CodeAct |
|------|-------------|---------|
| 单步表达力 | 一次工具调用 | 任意逻辑（循环/分支/变量） |
| 模型往返 | 每步一次 | 多步合并为一次执行 |
| 中间结果 | 全部回传上下文 | 留在沙箱，只回传最终输出 |
| 延迟与 token | 高 | 显著更低 |
| 安全性 | 天然可控 | 依赖沙箱隔离 |

## 为什么更有效

两个直接收益：其一，延迟与 token 下降——中间数据不必挤进上下文，大表格在沙箱里处理完只回传结论；其二，表达力上升——"对每个文件跑一遍检查并汇总失败项"用代码是五行，用函数调用是十次往返。此外，主流模型在训练语料中见过的代码远多于私有工具调用的 JSON 格式，用代码组织行动更符合模型的"母语"。

## 代价与前提

CodeAct 把安全的赌注押在沙箱上：生成的代码能做任何事，必须有文件系统、网络、资源限额的隔离，以及超时与审批机制。工具需要以代码可调用的形式暴露（如 Python 函数库），而非仅提供 JSON Schema。它最适合数据处理、批量操作等"中间步骤多、中间产物大"的任务；简单的一两步任务，传统函数调用反而更直观、更可控。
