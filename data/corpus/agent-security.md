# Agent 安全

## 为什么 Agent 安全是新问题

传统应用的安全边界清晰：代码逻辑是开发者写的，输入是用户给的。Agent 打破了这条边界——模型的行为由自然语言驱动，而它处理的每一段文本（网页、邮件、文件）都可能含有攻击者注入的指令。Agent 有工具、有权限、会自主行动，被误导的代价远高于"说错一句话"。

## 主要威胁

- **提示注入（Prompt Injection）**：恶意指令藏在 Agent 读取的内容里（间接注入）或直接来自用户（直接注入），诱导 Agent 违背系统提示词；
- **工具滥用**：Agent 被诱导执行危险操作——删文件、转账、把数据发给外部地址；
- **数据外泄**：私有数据（对话历史、文件内容、密钥）被带出问题、恶意 URL 回传等方式泄露；
- **权限蔓延**：Agent 继承了部署者的高权限，攻击面随之放大。

## 防御原则

- **最小权限**：每个工具只授予完成任务所必需的最小权限，文件系统限制在工作目录，网络访问设置白名单；
- **审批拦截**：不可逆、高副作用的操作（写、删、发、付）默认要求人工批准；
- **沙箱隔离**：代码执行类工具放进沙箱，与宿主环境隔离；
- **输入区分**：信任级分层——系统指令 > 用户输入 > 工具返回内容，后者永远不被当作指令执行；
- **失控保护**：限制循环轮次与预算上限，阻断无限运行。

## 在 Microsoft Agent Framework 中的对应关系

MAF 的 Harness 默认提供工具审批、沙箱、失控保护与可观测性，安全控制是运行时的一等职责而非事后补丁。安全工程的现实是：没有任何单一防线可靠，深度防御（权限 + 审批 + 沙箱 + 审计日志）叠加才是可行解。
