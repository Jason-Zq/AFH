# Agent 提示词工程

## 与普通对话提示词的区别

Agent 的系统提示词要同时约束"想什么、用什么、产出什么"，篇幅更长、结构更强。一份可维护的 Agent 提示词通常分五个板块。

## 角色设定

用一两句话界定身份与能力边界："你是研究助手，负责基于本地文档库回答问题"。避免堆砌人格化描写——角色越具体，任务越聚焦；人格越花哨，行为越不可控。

## 工具使用指引

每个工具写清三件事：**做什么、何时用、何时不用**。例如"web_search 用于获取最新公开信息；本地文档能回答时不要调用"。工具歧义是误用的主要来源，指引比工具数量更重要——宁可少而明确。

## 输出契约

明确规定最终产物的格式：纯文本还是 JSON、是否标注来源、篇幅上限。有下游程序消费时应配合结构化输出机制，而不是只靠提示词祈祷格式正确。

## 少样本示例

给 1–3 个"输入→思考→工具调用→输出"的完整样例，是校准行为最有效的手段。示例要覆盖典型路径与关键边界（如"资料不足时如何回答"），但不宜过多——示例会占用每轮上下文。

## 负面约束

明确列出禁区："不要编造引用与 URL""不要调用未提供的工具""资料不足时明说不知道"。负面约束是抑制幻觉与越权行为性价比最高的提示词手段，但要具体、可判定，空泛的"要诚实"几乎没有效果。

## 迭代方法

提示词工程是实证活动：建立失败案例集，每次只改一处，用回归集验证。把提示词当代码管理——版本化、可回滚、有变更说明。
