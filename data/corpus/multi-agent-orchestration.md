# 多智能体编排模式

## 为什么需要多智能体

单一 Agent 的能力受限于上下文窗口与提示词容量。把复杂任务拆给多个职责单一的 Agent 协作，可以获得：更专注的系统提示词、更清晰的职责边界、可独立替换的组件，以及并行处理带来的吞吐提升。编排（Orchestration）就是规定这些 Agent 如何接力的方式。

## 五种主流编排模式

### 1. 顺序（Sequential）

Agent 排成流水线，前一个的输出是后一个的输入。典型场景：检索 → 分析 → 写作。优点是确定性强、易于追踪；缺点是串行耗时。Microsoft Agent Framework 中用 `AgentWorkflowBuilder.BuildSequential` 构建。

### 2. 并发（Concurrent）

多个 Agent 同时处理同一输入（或同一任务的不同侧面），最后由聚合器合并结果。典型场景：多角度评估、多来源检索。优点是快；缺点是需要处理结果冲突。对应 `BuildConcurrent`。

### 3. 移交（Handoff）

一个"分诊"Agent 根据输入内容把任务连同完整上下文转交给最合适的专家 Agent，专家也可以再转交。典型场景：客服路由、多学科问答。对应 `CreateHandoffBuilderWith`。

### 4. 群聊（Group Chat）

多个 Agent 在一个共享对话里轮流发言，由管理器（如轮询管理器、模型驱动的管理器）决定下一个发言者与结束时机。典型场景：头脑风暴、红队评审。对应 `CreateGroupChatBuilderWith`。

### 5. Magentic

源自微软研究院 Magentic-One 的通用模式：一个编排器维护"任务账本"（进度、事实、猜测），动态指挥若干专业 Agent（浏览、代码、文件、终端）协同解决开放式复杂任务。适合任务结构事先未知的场景，代价是更高的令牌消耗与延迟。

## 选型建议

- 流程固定、步骤明确 → 顺序；
- 子任务互不依赖 → 并发；
- 输入类别决定处理方式 → 移交；
- 需要多视角碰撞 → 群聊；
- 开放式复杂任务、步骤无法预知 → Magentic。

这些模式在同一套工作流 API 上实现，切换编排风格不需要重写 Agent 本身——这是框架级统一抽象的核心价值。
