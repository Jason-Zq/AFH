# Agent 典型失败模式

## 循环失控

Agent 反复调用同一工具、原地兜圈，无法收敛到答案。

**对策**：硬性最大轮次与最大 token 预算；检测连续重复的（工具, 参数）对并强制中断；要求模型每轮陈述"本轮新信息是什么"。

## 目标漂移

长任务中模型逐渐忘记原始目标，开始优化无关的子问题。

**对策**：把原始需求固定在每轮上下文可见处；用待办列表把计划外显化，每步对照勾选；阶段结束做"目标对齐检查"。这正是现代 Agent Harness 内置计划模式的动机。

## 工具误用

选错工具、参数编造、或对工具返回结果误读。

**对策**：工具描述写清"何时用、何时不用"；参数用强类型 Schema 校验；失败结果原样返回给模型让其纠错，而不是吞掉异常。

## 上下文溢出

多轮工具结果堆积，挤爆上下文窗口，早期关键信息被截断。

**对策**：对冗长工具输出做摘要或落盘后只留引用；定期压缩历史（保留结论、丢弃过程）；为大任务拆分子代理，各自持有独立上下文。

## 级联幻觉

一步编造的事实被后续步骤当作前提引用，错误沿链条放大，最终输出"逻辑自洽的谎言"。

**对策**：关键事实要求标注来源；检索类证据原样保留、禁止改写；最终答案做忠实度校验（结论是否被证据支持）。

## 通用防线

- 一切失败模式的第一道防线是**可观测性**：完整记录思考与工具调用轨迹；
- 第二道是**护栏**：预算、轮次、审批人环节；
- 第三道是**可恢复**：检查点回滚而非从头重跑。Microsoft Agent Framework 的 Harness 正是把这三层打包成默认配置的尝试。
