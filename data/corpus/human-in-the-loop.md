# 人在回路（Human-in-the-Loop）

## 为什么需要人在回路

Agent 的自主性越强，犯错代价越高。完全自动化适合低风险、可逆的任务；涉及资金、数据删除、对外发布等操作时，正确的设计是把人类判断嵌入执行回路——让 Agent 停下来等人确认，而不是事后补救。

## 三种介入形态

- **审批（Approval）**：Agent 执行敏感工具前暂停，向人展示操作内容与参数，获得批准后继续。最常见、最容易实现；
- **中断/恢复（Interrupt/Resume）**：长任务运行中人可以随时打断、修正方向、补充信息，Agent 从断点恢复而非重来。这要求运行时持久化执行状态；
- **引导（Steering）**：人主动参与中间决策，如从 Agent 给出的多个方案中挑选，或在规划阶段修改计划。

## 审批规则设计

好的审批设计在"安全"与"打断疲劳"之间取平衡：

- **按风险分级**：只读操作放行，可逆写操作记录后执行，不可逆/高副作用操作强制审批；
- **审批信息要充分**：展示完整命令、目标路径、影响范围，让人有能力判断，而不是只会点"同意"；
- **支持批量与策略豁免**：重复性安全操作允许"本次会话内不再询问"，避免审批轰炸导致无脑全批；
- **拒绝路径可走**：人可以拒绝并给出理由，Agent 据此调整计划而非简单终止。

## 在 Microsoft Agent Framework 中的对应关系

MAF 提供函数调用中间件机制，可在工具执行前插入自定义拦截逻辑；Harness 层则内置了工具审批能力，危险操作默认触发人工批准流程，且可通过选项单独关闭。中间件管"拦在哪"，审批流管"谁来批"——两者组合即可实现完整的分级审批策略。
