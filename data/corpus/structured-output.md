# 结构化输出

## 定义

结构化输出指让模型按预定模式（通常是 JSON Schema）返回机器可解析的结果，而不是自由文本。它是 Agent 与下游程序之间的"输出契约"：工具路由、数据入库、UI 渲染都依赖格式稳定。

## 三个实现层级

| 方式 | 原理 | 可靠性 |
|------|------|--------|
| 提示词约定 | 在提示词中描述 JSON 格式并要求"只输出 JSON" | 弱，模型可能加废话或截断 |
| JSON 模式 | 厂商提供 response_format 参数，约束输出为合法 JSON | 中，保证语法合法，不保证字段语义 |
| Schema 约束解码 | 解码阶段按 Schema 屏蔽非法 token | 强，可做到字段级保证 |

## 厂商支持差异

各家 API 对结构化输出的支持并不一致：有的支持完整 JSON Schema 约束解码，有的只保证"输出是合法 JSON"，对 required、嵌套、枚举等关键字的支持范围也有差别；还有厂商把结构化输出与函数调用共用一套机制。接入多厂商时，应以最弱支持面设计 Schema——避免过深的嵌套与冷门关键字，并在文档中核实各家具体限制。

## 容错解析

即便使用约束解码，工程上仍需容错层：

1. 截取首个 `{` 到末个 `}` 之间的内容，剥离模型可能附加的散文；
2. 用 Schema 校验，失败时把错误信息回喂模型要求修正（自愈重试，通常一两次即可收敛）；
3. 超过重试上限则走人工兜底或降级路径，绝不让坏数据静默流入下游。

## 实践要点

- Schema 即文档：字段命名与描述会直接影响模型填值质量；
- 可选字段宁可缺失也不要让模型编造，校验层区分"必填缺失"与"可缺省"；
- 结构化输出与流式可以共存，但增量解析需容忍不完整 JSON。
