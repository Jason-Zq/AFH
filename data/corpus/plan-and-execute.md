# Plan-and-Execute 模式：先规划，再执行

## 定义

Plan-and-Execute（计划-执行）是一种将任务分解与任务执行分离的智能体架构模式：先由"规划器"（Planner）生成一份完整的分步计划，再由"执行器"（Executor）逐步执行，必要时根据执行结果重新规划（Replan）。

## 与 ReAct 的对比

| 维度 | ReAct | Plan-and-Execute |
|---|---|---|
| 决策粒度 | 每步临时决策 | 先全局规划再执行 |
| 长任务表现 | 容易绕路、遗忘目标 | 目标感强、进度可追踪 |
| 令牌消耗 | 每步都带完整历史 | 规划一次，执行步可精简上下文 |
| 灵活性 | 对意外情况即时响应 | 计划可能过时，需要重规划机制 |
| 可解释性 | 思考轨迹外显 | 计划本身即文档 |

## 典型实现结构

1. **Planner**：接收用户目标，输出有序步骤列表（通常是结构化输出，如 JSON 数组）；
2. **Executor**：逐条执行步骤，每步可以是工具调用、检索或子 Agent 委派；
3. **Replanner（可选）**：每执行若干步后检查进度，发现偏差时修订计划。

## 实践要点

- **计划要可执行**：步骤应具体到"调用什么工具、查什么内容"，避免空泛的"研究一下"；
- **保留进度状态**：已完成步骤、中间结论需要持久化（这正是 Harness 待办列表的职责）；
- **设置重规划触发器**：步骤失败、结果与预期不符、步骤数超过阈值时触发；
- **限制计划深度**：过深的计划意味着不确定性累积，通常 3-7 步为宜。

## 在 Microsoft Agent Framework 中

Harness 的 AgentModeProvider 内置了 plan / execute 两种模式：Agent 接到复杂任务时先进入 plan 模式输出计划（同时落入待办列表），再切换到 execute 模式逐项完成。这意味着开发者不必手写 Planner/Executor 两个角色，Harness 用同一模型加模式切换即可实现 Plan-and-Execute 的行为。
