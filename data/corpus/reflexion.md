# Reflexion 反思模式

## 定义

Reflexion 是 2023 年提出的 Agent 模式：让 Agent 在任务失败或完成后进行自我批评，把反思结论写入记忆，在下一次尝试中利用这些"经验教训"改进表现。核心思想是用语言化的口头反馈替代参数更新——不微调模型，也能跨尝试学习。

## 工作流程

一个典型的 Reflexion 循环包含三个角色：

1. **执行者（Actor）**：按常规方式（如 ReAct）执行任务，产生轨迹；
2. **评估者（Evaluator）**：判断任务成败——可以是单元测试、环境反馈或模型评分；
3. **反思者（Self-Reflection）**：失败时分析轨迹，生成一条自然语言的反思（"我错在直接猜答案而没有先验证接口签名"），存入情景记忆。

下一轮尝试时，这条反思被注入上下文，Actor 带着"上次的教训"重来，直到成功或达到尝试上限。

## 与 ReAct 的差异

| 维度 | ReAct | Reflexion |
|------|-------|-----------|
| 学习粒度 | 单次任务内的推理-行动交替 | 跨尝试的经验积累 |
| 反馈来源 | 每一步的环境观察 | 任务级成败 + 事后反思 |
| 状态持久化 | 仅当前上下文 | 反思写入记忆，多轮复用 |
| 开销 | 低 | 每次尝试多一次评估与反思调用 |

ReAct 是"边做边想"，Reflexion 是"做完复盘、下次更好"。两者可叠加：用 ReAct 当 Actor，外面套 Reflexion 循环。

## 适用场景

适合有明确成败信号的域：代码生成（测试可判对错）、可验证的推理题。不适合成败模糊、奖励稀疏的开放式任务——没有可靠评估者，反思就成了自说自话。同时要控制尝试上限，否则反思循环会演变成烧 token 的重试。
